# 狗头军师 · Mac 微信副驾（实验版）

把 Jev Mac 的窗口 OCR 和辅助功能回填接到狗头军师的分析工作流；可选 TypeSafe Jev 先选策略，再由聊天模型生成回复。
现有 Codex Skill 照常使用；此目录是可选的独立桌面入口。

第一版按需操作：**读取当前微信 → 核对文字和说话人 → 分析 → 复制或填入草稿 → 用户发送**。
悬浮窗会给出首选行动、事实／推测／未知、观察窗口、停止条件和至多三条带理由、代价的候选。
它按用户选择的场景加载话术编排器和一份主题知识，不只是套一种“军师语气”。

日常界面是 **可拖动的墨绿悬浮球 + 420 × 640 暖白圆角面板**，置顶显示在微信旁边。
点击悬浮球展开／收起；面板右上角 × 只收起，不退出。首选浅绿卡片、备选暖灰卡片，
每条都有复制／填入按钮。长回复自动增高并支持滚动；只显示实际生成的候选，不填充虚构答案。
顶部依次显示当前对象／关系阶段／目标、**对方可能的意图**、原文依据、军师建议。
意图下方显示“判断把握 · 62%（模型估计）”一类提示：由回复模型随主要意图生成 0–1 自评数值，非统计校准概率。
它与 Jev 策略置信度、候选推荐权重分开。证据不足时为 null，显示“暂无法判断”；缺失字段也不伪造数字。
本地校验数值范围、有限性及对应意图和事实，拒绝字符串、布尔值、越界值和无事实的置信度；口吻改写保留原意图把握。
下方是 **候选回复排序**：卡片显示 `#1 · 70%` 等推荐权重，理由与代价通过“为什么这样回”展开。
百分比是本轮候选的相对偏好，不是对方回复率、关系成功率或 Jev 的策略置信度；点 ⓘ 可查看说明。
Jev 策略置信度放在详细分析中。点齿轮或对象旁按钮进入设置页：查看隐藏的密钥配置状态、修改回复模型、
设置对象、关系阶段和目标，选择稳健／会撩／直接口吻、简短／适中／详细长度及 1–3 条候选，
调节不透明度或用合成对话测试接口。回复偏好真正约束模型请求与返回校验。
在设置页“接口与模型”点击 **配置接口**，可分别在遮挡输入框中填写 DeepSeek 和 TypeSafe Jev Key，点击各自的“保存 Key”后立即写入本项目专用的 Mac 钥匙串条目并更新当前窗口；也可单独移除。输入框不会回显已有 Key，空白输入不会覆盖已有值。此页“连通测试”使用合成对话，会调用已配置的接口并产生少量用量。离线演示禁用密钥操作。
DeepSeek 的官方地址固定用于这条钥匙串配置；回复模型名称仍在主设置页修改，图片识别使用官方 `deepseek-flash`。Jev 默认使用 `jev-1.13.0`，保存 Key 后启用可选策略层。显式环境变量优先于钥匙串；自定义回复接口继续通过环境变量设置，配置页会提示当前覆盖状态。

![接口配置窗口的离线演示截图](../../documentation/design/provider-config-preview.png)

*图：真实界面的离线演示，输入框为空，不读取或展示任何已保存密钥。*

“读屏与悬浮窗 → 识别方式”可选 **Apple Vision · 本地**（默认）或 **DeepSeek · 图片识别**。
选择 DeepSeek 时，程序截取当前微信窗口的聊天区域（不含侧边栏和输入框），将截图作为图片发给官方
`deepseek-flash` 识别；使用现有项目专用 DeepSeek Key，会产生图片 API 用量。它是支持看图的通用模型，
不是本地 OCR。设置页会标明上传和计费，未选中时不上传截图。识别后仍需核对会话名、双方归属和错字。
接口依据：[DeepSeek 图像理解官方文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)。

候选采用话术编排器的自然口吻规则：只参考当前会话中可靠归属于用户的原话，贴近其用词、长度和标点；
没有样本时用朴素口语。分析和可发送文字分开，不强加语气词、土味情话或策略解释，最多给设定数量，
不为凑数换词重复。全部内容都标为说话人待确认或 OCR 待核对时，本地阻止模型请求，先请用户核对。
模型、偏好及透明度保存在被 Git 忽略的 `settings.local.json`；关系背景、聊天和密钥不写入该文件。
对象背景在本轮内存中彼此独立，可以明确将已有对象绑定到当前窗口；窗口标题不是可靠的账号或会话 ID。
点击底部“读取对话／重新分析”，直接在悬浮窗里核对编辑，再点“确认并分析”。
“更像我一点”让当前回复模型参考本轮可靠归属于用户的用词和句长，保留分析和策略，只调整候选口吻并重新评分；不会再次调用 Jev。
它不训练模型，不跨会话建立口吻档案；用户原话样本不足时只能改成朴素口语，不能保证像本人。
“详细分析”打开统一暖白墨绿卡片窗口，分为“分析详情”和“核对原文”两个页签。意图、事实、推测、未知、下一步、停止条件和候选分区显示。
原文与补充背景修改后旧分析作废，重新确认后分析自动返回结果页；复制／填入动作与悬浮窗使用同一份候选。
右键悬浮球可退出。`./start.command --details` 可启动后直接打开详情页。

悬浮面板标题栏的 **K线** 按钮可打开独立的关系趋势窗口（也可用 `./start.command --trend`）。
该页内置五组**手工设定的事件示意 K 线**，直接显示升温、降温、失约与修复等文章案例；
示意指数的开高低收随源码提供，不由模型计算，也不是爱意或关系成功概率。
用户也可手动导入带 `timestamp,sender,message` 三列的 UTF-8 CSV；`sender` 必须已核对为 `me` 或 `other`。
对导入记录，程序按有消息的日期绘制**消息方向 K 线**：每条对方消息使累计净差 +1，每条我的消息使其 −1，
当日形成开、高、低、收，图上最多展示最近 45 个有消息的日期。可选 `event` 列用于人工标记关键事件；
合成案例的关键事件来自案例清单。两种图在窗口中明确标注计算口径，不混作同一种关系评分。
邀约兑现、冲突修复和明确边界仍需结合事件阅读。
导入文件仅在本机内存中用于绘图，不调用 Jev／回复模型，也不写入关系档案；清空本轮或切换对象会清除已载入的图。
当前微信 OCR 只读取可见窗口，缺少完整时间线，因此不会把一屏聊天伪装成长期趋势。`--demo --trend` 可离线查看合成图。
在详细窗口勾选“自动读取对话”按所选 OCR 方式读取；若选择 DeepSeek，画面变化时上传聊天区域截图，
启动自动读屏时会提示图片用量。设置页另有默认关闭的“新消息自动分析”：
先读取并核对当前会话，再开启并确认数据发送范围。只对当次选定窗口和标题生效；
文字稳定至少两秒、末条来自对方、没有低置信度或方向未知标记时才调用模型。
同一文本不重复调用，调用至少间隔十秒；开启时已有消息不重复分析。换会话不扩展授权范围。
编辑设置、资料、详情或核对文字时暂停轮询。重启和清空本轮都关闭自动分析。

“关系档案”复用项目 `scripts/memory_store.py`，首次需在界面明确同意。
保存设置时仅更新用户填写的当前对象有限字段，不从模型输出自动写入事实，不保存整份聊天。
支持查看、暂停／恢复、撤销上次保存、删除当前对象（再次确认）和撤回同意。
未启用时不创建档案，暂停时不召回或更新，选定对象后才载入具体资料。
撤销影响已保存档案，当前本轮编辑保留并明确提示。MBTI 和主观评分可留空，不擅自评分。

## 安装与启动

需要 macOS、Python 3.12 及 `uv`。`./start.command --settings` 可直接打开设置。在本目录执行：

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
```

先预览合成场景，不读微信、不联网、不回填：

```bash
.venv/bin/python -B app.py --demo
```

正式启动后，推荐在“设置 → 接口与模型 → 配置接口”中直接填写并保存两组 Key。也可以继续通过终端保存到项目专用 Mac 钥匙串（隐藏输入，不进入命令历史）：

```bash
security add-generic-password -a default -s ai.goutoujunshi.deepseek -U -w
./start.command
```

未设置下面三项环境变量且存在该条目时，使用官方 `https://api.deepseek.com` 和 `deepseek-flash`。
DeepSeek 请求关闭思考模式，并启用 JSON 输出，适合本项目的回复草稿。
模型名称及参数见 [官方文档](https://api-docs.deepseek.com/zh-cn/)。
也可以在当前终端显式配置 OpenAI 兼容接口：

```bash
export GOUTOU_API_BASE='https://api.deepseek.com/v1'
export GOUTOU_MODEL='deepseek-flash'
# 用终端交互读取密钥，避免密钥进入命令历史（zsh）。
read -rs 'GOUTOU_API_KEY?API Key: '
export GOUTOU_API_KEY
echo
./start.command
```

如果选择本机 Ollama，先自行准备可用模型，然后设置 `GOUTOU_API_BASE=http://localhost:11434/v1`、
`GOUTOU_MODEL=你的模型名`，不需要密钥。程序不会自动安装或下载模型。
未配置 Jev 时，由一个聊天模型完成策略和回复。配置 Jev 后先调用 TypeSafe 选策略，再调用聊天模型；TypeSafe Key 不能代替回复模型的 Key。
没有配置时只可读取／编辑文字，分析会明确提示；不会继承其他工具的 Key 或使用公共中转。

打开微信聊天窗口，在系统设置 → 隐私与安全中给启动终端授予“屏幕录制”权限，重启终端和本程序。
“填入”另需“辅助功能”权限。若微信版本未开放可验证的输入控件，使用复制手动粘贴。
终端中的环境变量只对从该终端启动的程序生效；直接双击启动文件可能读不到配置。

## 可选 Jev 策略层

Jev 通过 TypeSafe 官方 `https://api.typesafe.ai/v1/systemone` 调用，默认固定 `jev-1.13.0`。
它读取核对后的文字、会话标题、场景、背景和项目话术指南中的策略章节，从七种主策略中选一个。
聊天模型再结合同一份 Skill 和场景资料生成回复；若它返回不同的主策略，会拒绝展示该批候选。
有两个或三个候选时，再使用同一回复模型和接口独立评分，结合当前聊天、对象背景、目标、口吻与代价，
按分数归一化，并用最大余数法让整数权重合计 100%。这一步会增加一次请求、API 用量及等待时间。
排序移动完整候选，原文、理由、代价及复制／填入索引保持一致。评分失败保留原生成顺序，显示“排序暂不可用”，不显示伪造数字。
只有一个候选时显示 100%，仅代表唯一候选，不发起评分请求；没有候选时直接展示本轮建议。
Jev 失败不会静默换成另一个模型，也不会自动重试。详细分析显示策略来源与模型置信度，置信度不代表回复成功率。

Mac 推荐将 Key 存入项目专用钥匙串（命令会隐藏输入，不把 Key 放进命令历史）：

```bash
security add-generic-password -a default -s ai.goutoujunshi.typesafe -U -w
```

启动时仅查询这个条目；也可显式设置 `GOUTOU_JEV_API_KEY`，优先于钥匙串。
`GOUTOU_JEV_ENABLED=0` 可关闭 Jev，`GOUTOU_JEV_MODEL` 可显式选择其他 TypeSafe 版本。
回复模型单独使用 DeepSeek 钥匙串条目或 `GOUTOU_API_BASE`、`GOUTOU_MODEL`、`GOUTOU_API_KEY`，两组密钥不混用。
保存的 DeepSeek Key 只会用于官方根地址或 `/v1`，不会继承到其他接口。显式环境变量 Key 优先。
不读取其他软件的 Key，不跟随接口重定向。

以下命令会用合成对话真实调用一次 Jev，可能产生 API 用量；不会读微信或调用回复模型：

```bash
.venv/bin/python -B check_jev.py
```

完整分析需两个服务都可用。`--demo` 始终离线，不读取钥匙串，也不调用 Jev。
运行 `.venv/bin/python -B check_pipeline.py` 可用合成对话真实验证 Jev → 回复模型链路，会产生两项 API 用量，不读取或回填微信。

## 数据、范围和限制

- 默认只在点击读取时截图；主动开启自动读屏后每两秒检查一次画面。本地选项由 Apple Vision 识别；DeepSeek 选项仅在画面变化时向官方接口上传裁剪后的聊天区域 PNG，不保存截图到本项目文件。云端识别失败会报错，不会静默改用另一条路径。截图通常在内存中，系统抓图失败时会使用自动清理的临时 PNG。
- 核对并点击分析后，当前文本、标题、补充背景和选中的知识内容发送至窗口显示的回复模型服务；启用 Jev 时，相同本轮文字和策略指南先发送至 TypeSafe。分析阶段不额外上传截图。
- 本程序不保存整份聊天或分析；明确启用后才通过现有记忆脚本保存精简对象资料。Jev 和 DeepSeek Key 可保存在系统钥匙串，不写入仓库或明文配置。OCR 选项名保存在被 Git 忽略的设置文件中。复制会按用户点击把候选写入剪贴板。
- OCR 的左右布局不是可靠身份验证；须由用户核对。群聊、图片表情、引用、长消息和新版本布局尚未专项验证。
- 已填的草稿保留，候选追加到末尾。回填前按本轮所选 OCR 方式重新读取并比对会话标题、窗口和可见消息；变化或识别不明时拒绝填入。DeepSeek 未读到明确会话名时仅可复制，不可回填。
- OCR 比对与辅助功能写入无法成为微信内部的原子事务；点击后仍请核对收件人和草稿，程序从不发送。
- 输入变化会清除候选，切换会话使用对应对象的本轮背景，过期结果不会覆盖新输入。只有显式启用新消息自动分析后才按范围调用模型；不从模型输出自动写入档案。
- 这是源码实验入口，尚不是签名／公证的 `.app`，也没有声称完成各版微信的真机验收。

## 验证

仓库根目录运行：

```bash
python3 -B scripts/validate_skill.py
python3 -B -m unittest discover -s tests -v
```

离线测试覆盖说话人不确定性、知识按需加载、响应契约、会话切换、过期结果、接口地址和错误脱敏。
离线测试还覆盖 Jev 策略响应校验、服务调用顺序、密钥隔离、错误脱敏及策略冲突时拒绝候选。
真实运行需另外验证：OCR 内容、说话人纠错、两个模型的输出质量、切换会话后拒绝回填、保留草稿、只填不发。

[jev-chat/jev-chat-jarvis-mac](https://github.com/jev-chat/jev-chat-jarvis-mac)，
固定提交 `afb58cf53d098e314a1368d15e13ab5330015688`，MIT 许可见 [vendor/LICENSE](vendor/LICENSE)。
这里只移植采集与 AX 输入模块，移除了 `fill.py` 的视觉键盘回退分支；未引入上游的模型、默认中转或密钥。
